## 待定（按该解决的先后排）

### 1. 语料是什么 —— 阻塞其余一切

导师会提供数据集，但形态未知。需要问清楚：

- 是 PDF 讲义 / 教材 / 课程网页 / 题库 / 论坛问答？
- 中文还是英文？（决定 embedding 选型：中文优先 bge 系列）
- 有多大？多少篇、多少页？
- 有没有现成的结构（章节、标题层级）？
- 有没有配套的问答对可以直接当评估集？

**没拿到这个之前，切分策略、解析方案、embedding 选型都定不下来。**

### 2. "个性化"到底怎么落地

这是最容易做虚的一块。目前想到的几种做法，深浅差别很大：

| 做法 | 成本 | 能不能写进报告 |
|---|---|---|
| 学生自选难度（初学 / 进阶），改 prompt | 极低 | 只能算基线 |
| 从对话历史推断掌握程度，动态调整 | 中 | 可以，但要能评估 |
| 维护学生画像（学过哪些章节、错过哪些概念），检索时按画像做元数据过滤 | 高 | 亮点，但要设计画像的更新机制 |
| 按学生水平选不同的检索片段（同一概念的入门段 vs 严谨定义段） | 中 | 有意思，和 RAG 结合最紧 |

**倾向**：至少做到第二档，把第四档当作加分项试一试——因为它是唯一把"个性化"和"检索"真正耦合起来的方案，其余几种本质都只是改 prompt。

**难点在评估**：怎么证明个性化"有用"？可能需要设计一套人工评分维度（解释深度是否匹配、有没有跳步、术语是否解释过）。这套评分标准要早点定。

### 3. 评估集怎么建

- 30~50 条问答对，覆盖不同难度和不同章节
- 每条要标：标准答案、支撑片段（用于算 Recall@k）、难度层级（用于测个性化）
- 来源：从语料里人工出题？还是用 LLM 生成再人工筛？（后者快，但要防"照着某一段出题"导致检索任务过于简单）

### 4. 模型对比的范围

官方点名 Llama / Qwen / Gemma / GPT。需要确认：

- 本地能跑多大的模型？有没有 GPU？（决定是全部本地推理，还是混用 API）
- embedding 模型对比几个？（bge-small/base/large-zh、bge-m3、gte…）
- 对比要控制变量：换 LLM 时检索层必须完全冻结，否则结论不成立

### 5. 技术栈

未定。倾向轻量：Python + 一个向量库（Chroma / FAISS / Qdrant 三选一）+ 自己写流水线，不套重框架——因为要逐个换旋钮做消融，框架的封装反而碍事。
