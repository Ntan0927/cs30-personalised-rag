## 标题

Personalised AI Learning Assistant using Retrieval-Augmented Generation and Large Language Models

## 背景与问题

生成式 AI 和 LLM 有潜力通过个性化辅导、自动反馈和智能学习支持改变高等教育。但通用 LLM 存在三个问题：

1. 会给出不准确的回答
2. 会产生幻觉
3. 无法访问可信的教育资源

本项目用 RAG 来解决——把教育资源检索与 LLM 生成结合，提供**准确、可解释、有证据支撑**的回答，并能根据学生的需求和学习情境调整解释方式。

## 需要构建的端到端系统

- 教育文档处理（document processing）
- 语义检索（semantic search）
- 向量数据库构建
- 检索优化
- Prompt engineering
- 回答评估（response evaluation）

并且要**横向对比不同 LLM**（Llama、Qwen、Gemma、GPT 系列）与不同 embedding 模型，分析它们在提升回答准确率、减少幻觉、生成有用教学解释上的效果差异。

## 三项官方目标

### 1. 构建检索增强的生成式 AI 导师

- 建立领域专属的教育知识库
- 实现结合文档检索与 LLM 生成的 RAG 流水线

### 2. 提升 AI 回答的准确性与可靠性

- 研究检索策略、embedding 模型、prompt engineering 技术
- 评估减少幻觉、提升证据支撑的方法

### 3. 开发并评估个性化学习支持

- 根据学生需求与学习情境生成自适应解释
- 评估回答的质量、有用性与教育价值

## 读题笔记

- "**Personalised**" 在标题里，不是附加项。三个目标里有一个整块是它，报告缺这块会明显失分。
- "**compared / analyse effectiveness**" 是明确要求的动作。这意味着项目的骨架是**受控对比实验**，不是"做一个能跑的 demo"。
- "**evidence-based / explainable**" 指向引用标注与溯源，不只是答对。
- 数据集由导师提供，所以语料的形态（PDF 讲义？课本？题库？）会直接决定文档处理层怎么做——**这是最该尽早问清楚的一件事**。
